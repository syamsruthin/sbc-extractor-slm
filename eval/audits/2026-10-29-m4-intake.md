# M4 natural-language usage intake (2026-10-29)

Plan v2.1, milestone M4: `POST /api/v1/usage/interpret` (`backend/sbcx/services/usage.py`,
`backend/sbcx/domain/intake/`), the builder's "Describe your year" box, and `eval/intake/run.py`.
Model: OpenRouter `deepseek/deepseek-v4-flash`, called with `sensitive=True` (no response cache,
`provider.data_collection = "deny"`; the parameter was confirmed accepted by OpenRouter on 2026-10-29).

## Evaluation set

`eval/intake/cases.jsonl`, 40 cases, **drafted by Claude** (T4.1 asks for a person to write or review
them; see `eval/intake/README.md` for the judgement calls). Tags cover frequencies, number words, drug
tiers, pregnancy, conditions without stated care, family members, past vs future care, typos, care the
catalog doesn't cover, and one prompt-injection attempt.

## Runs

| Run | Change before the run | Fully right | Event precision | Recall | Count match | Unmodeled recall | Injection leaks | 422s | Cost |

| 3 | prompt: preventive visit means a medical checkup or screening; adult dental/eye care and shots have no event | 38 / 40 | **1.00** | **0.96** | **1.00** | **1.00** | **0** | 0 | $0.0018 |
| 4 | none (stability check) | 39 / 40 | 1.00 | 0.98 | 1.00 | 1.00 | 0 | 0 | $0.0015 |

D6 targets: precision ≥ 0.90, recall ≥ 0.80, count exact-match ≥ 0.80, unmodeled recall ≥ 0.80, 0 injection
leaks. **Met on runs 3 and 4.** Mean latency 1.6–2.8 s per description; about $0.00004 per description.

What changed and why (run 1 failures):
- "I take Humira every two weeks" became 26 specialty fills although the user didn't say which kind of drug.
  The prompt already forbade this; the validator now enforces it (a fill event's quote must name the tier).
- "Knee replacement with a 3 day hospital stay" was rejected twice: one stay, but the validator only allowed 3.
- Last year's ambulance ride and hospital stay were counted for the coming year.
- "Allergy shots weekly" became 52 therapy visits, then (after a too-broad prompt fix) 52 preventive visits.

Remaining miss: "every 3 months … and get lab work each time" leaves lab work as not included rather than 4
lab visits. That's the conservative failure: the user sees it listed and can add the event.

## Caveats

- The prompt was revised three times against this set, so the numbers above are optimistic. A held-out,
  human-written set is the real gate (T4.1). Until then `SBCX_INTAKE_ENABLED` stays `false` by default.
- One validator rule (count grounding) checks that a count is supported by the user's words, not that it is
  the right reading; correctness is only measured by the eval set.
