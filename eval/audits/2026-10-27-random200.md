# Accuracy audit: 200 random SBCs (2026-10-27)

Parser `2.0.1` at audit time, `2.1.0` after the follow-up fixes (deterministic, no LLM fallback). 200 SBCs drawn at random (seed `20261027`) from the
1,829 local PDFs: 149 "extracted" labels, 41 reviewed, 9 cell-reviewed val, 1 gold.

## Results

| Check | What it measures | Result |
|---|---|---|
| Extraction | crashes | 0 / 200 |
| Agreement with v1.4 labels | 52,381 fields | **99.41%** (98.85% before the fix below) |
| Numbers printed in the PDF | 5,434 non-zero amounts and percentages | **100%**; nothing invented |
| Provenance page | cited page contains that service's row label | **99.1%** (94.2% before the fix below) |
| Hand audit vs PDF | 100 random values (80 service cells, 20 deductible/OOP amounts) read against the PDF table rows | **100 / 100** correct (95% lower bound ≈ 96.3%) |
| Disagreement adjudication | 30 random parser/label disagreements judged against the PDF | label right 26, ambiguous / convention 4, parser right 0 |

Agreement by field group (200 docs): money 99.39%, percent 99.56%, covered 99.60%, deductible
flag 99.45%, drug tier category 97.47%, plan info 96.60%; list F1: services before deductible 93.5%,
exclusions 99.3%. Reviewed v1.4 set (450 docs) after the fixes: 99.2% (was 98.7%). Gold: 96.9% (unchanged).

## Bugs found and fixed in this audit

1. **"0% coinsurance" became copay $0 + 0%.** The pipeline applied the v1.2-era `schema.normalize()`,
   which v1.4 conventions (and the prototype) don't use. That made the cell look like "No charge", which
   also skipped the deductible range in cost estimates. Replaced with `normalize_v14()`. Accounted for
   290 of the 601 original disagreements.
2. **Provenance page was wrong for generic cell text.** "No charge" or "20% coinsurance" was mapped to the
   first page containing those words. Rows are now located by their label, walking pages in template order.

## Error patterns found (from the adjudicated disagreements)

| Pattern | Example | Impact |
|---|---|---|
| Later-charge wordings not covered | "$5 copay/first 2 visits per year, then $45"; "$30 copay for the first three visits and 10% coinsurance thereafter"; "$5 / upfront visit; $40 / additional visit" | copay/coinsurance |
| OOP split when the network label comes first | "For network provider $6,550 individual / $13,100 family. For out-of-network…" → individual = 13,100 | money (headline) |
| Deductible flag scope with labeled parts | "Lab: … ; deductible does not apply. X-ray: 40%" → flag not applied to the first part | deductible flag |
| Whole row missed | children's eye/glasses rows in one WI family; SD home health; NH ER out-of-network | coverage |
| Drug tiers sharing one label cell | "Tier 1 Preferred Generic / Tier 2 Non-Preferred Generic" split oddly | tier alignment (prices right) |
| Plan name artifacts | issuer prefix kept; "Individual + Family I" read as part of the name | cosmetic |

Scripts: `extract.py`, `score.py`, `pdfcheck.py`, `handaudit.py` (session scratchpad, not committed).

## Follow-up fixes (parser 2.1.0)

Each pattern above was fixed against every occurrence in the 1,829-doc corpus, and checked for regressions
on the gold set, the reviewed v1.4 labels and the 326 cell tests after each change.

| Fix | What changed |
|---|---|
| Later-charge wordings | One rule finds the later price whether its marker comes after it ("… and 20% coinsurance thereafter", "/ additional visit") or before it ("then", "Additional visits:", "Subsequent visits"); also "Reimbursed first $100, then 50%" |
| Question rows split across table rows | An answer that starts in the row above ("For network provider - $6,550 Individual" + "/ $13,100 family …") is joined; an answer containing a literal pipe ("$6000 per person \| $12000 per group") is joined; "group" counts as family; "$6.000" reads as $6,000 |
| Deductible flag scope | A statement closing the first group of alternatives ("Lab: … or $75; deductible does not apply. X-ray: …") or standing alone right after it applies to that group; "after Deductible/prescription" is no longer cut off as if it were a part label |
| Missed rows | Rows pymupdf4llm rendered as "picture text" are turned back into table rows; an in-network price printed across both network columns (blank out-of-network cell) applies to both. Filling every empty cell from the pdfplumber view was tried and rejected (agreement fell to 99.1%) |
| Shared drug-tier labels | A cell naming several tiers is split only when a price cell lists one price per tier |
| Plan names | Header artifacts removed: text after " \| ", "Plan Type …" tails, leading dashes and "(domiciled in …)", doubled first word, corporate brand before the repeated brand |
| Cost engine (found by property tests while re-testing) | Low/high bounds are now the cheaper/dearer run, so low ≤ high always holds near the out-of-pocket cap |
